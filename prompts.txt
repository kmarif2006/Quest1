Before sending anything to the media pipeline, validate the inputs properly. The URL should be a valid http/https URL or local file path, and the dialogue should not be empty or whitespace-only. At the same time, don’t make dialogue validation too restrictive because valid targets may contain punctuation, numbers or non-English unicode text. Keep validation on both the frontend and backend since client-side validation can be bypassed.

Keep this phase strictly as a presentation layer over the existing system. Preserve the CLI and current search behavior, reuse the existing frame-serving/API routes where possible, and add focused tests for valid results, invalid inputs, no_match/failed states, duplicate search prevention and search again.
